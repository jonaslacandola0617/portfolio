## Purpose

CCNA labs on dynamic routing protocols come later in the curriculum — this lab is about
understanding what those protocols are automating, by doing it manually first. Three routers,
each with a directly connected LAN, needed static routes so every network could reach every other
network, plus a default route out to a simulated ISP.

## Commands Used

<CommandBlock title="R1 configuration" commands={["configure terminal", "ip route 192.168.20.0 255.255.255.0 10.0.12.2", "ip route 192.168.30.0 255.255.255.0 10.0.12.2", "ip route 0.0.0.0 0.0.0.0 203.0.113.1", "end", "write memory"]} />

## Configuration

Each router received one static route per remote LAN, pointing to the next-hop IP on the
directly connected link toward that network, plus R1 also carried the default route toward the
simulated ISP link.

## Expected Result

Every LAN should be able to ping every other LAN, and all three routers should be able to reach
the simulated internet host through R1's default route.

## Actual Result

<Callout type="success" title="Pass — after one correction">
All three LANs reached each other. The ISP ping failed on the first attempt (see Mistakes) and
passed after correcting the default route's next-hop address.
</Callout>

## Mistakes

I initially pointed R1's default route at the wrong interface IP — I'd copied the address of my
own Gi0/1 interface instead of the ISP-side next hop. `show ip route` showed the route installed
but traffic never left the router, which was the clue that the next-hop, not the route itself,
was wrong.

## Fixes

Removed the bad default route with `no ip route 0.0.0.0 0.0.0.0 <wrong-ip>` and re-added it with
the correct ISP-facing next hop. Re-ran `show ip route` to confirm a single, correct default
route before retesting.

## Lessons Learned

- `show ip route` confirms a route is *installed*, not that its next-hop is *correct* — always cross-check the next-hop against the topology diagram
- Floating static routes and default routes both deserve a second look before assuming a routing failure is protocol-related
