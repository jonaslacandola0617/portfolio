## Overview

A basic hardening step for any SSH-exposed box is knowing when someone is trying to brute-force
their way in. Rather than reach for a full SIEM immediately, I built a small script to understand
what a SIEM is actually doing under the hood: parsing logs, applying a rule, and raising an alert.

## Objectives

- Parse `/var/log/auth.log` for failed password attempts
- Group failures by source IP within a rolling time window
- Flag any IP with 5+ failures in 10 minutes
- Write a human-readable summary and (optionally) email it

## Configuration

```python
# monitor.py — simplified core logic
import re
from collections import defaultdict
from datetime import datetime, timedelta

PATTERN = re.compile(r"Failed password .* from (?P<ip>\d+\.\d+\.\d+\.\d+)")
WINDOW = timedelta(minutes=10)
THRESHOLD = 5

def scan(lines):
    attempts = defaultdict(list)
    for line in lines:
        match = PATTERN.search(line)
        if not match:
            continue
        ip = match.group("ip")
        attempts[ip].append(datetime.now())

    flagged = {ip: len(times) for ip, times in attempts.items() if len(times) >= THRESHOLD}
    return flagged
```

Running it on a schedule with cron:

## Troubleshooting

My regex initially missed IPv6-formatted log lines and dropped them silently. Since the goal was
learning the parsing logic rather than full protocol coverage, I documented the limitation instead
of scope-creeping the script, and left an IPv6 pattern as a "next iteration" note.

## Lessons Learned

- Most of the "SIEM magic" is honestly just disciplined log parsing plus a time-window rule
- Testing against a static sample file first made the logic much faster to debug than tailing a live log
- Writing the limitation down (no IPv6 support yet) is more useful to a future reader than pretending it's complete
